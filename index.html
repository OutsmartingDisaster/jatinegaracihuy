Spec before code

Write the PRD first.

Discipline before code. The PRD is the contract between you and your coding agent.

1

Shared understanding — user + decision agreed upfront.

2

Scope control — non-goals stop the agent from inventing features.

3

Measurable done — expected states, not "looks nice".

✗

Without it — agent guesses, scope creeps, output is hard to audit.

Anatomy of a PRD — everything from stack to pixels:

userpurposepages/flow tech stackDB schemaAPIUI/UX constraintsseed dataexpected statesnon-goals
Build in passes

Break it down. Ship it demonstrable.

Pass 01
Foundation

App shell, nav, DB schema, seed data, visible disclaimer.

Pass 02
Core journey

Pick an event → see risk + impact. One action, done well.

Pass 03
Quality

Mobile layout, error states, accessibility, attribution.

Pass 04
Polish

Methodology, screenshots, demo reset, clean README.

Why? Each pass is demo-able, has a small failure surface, and is easy to audit. Never start pass N+1 until pass N is verified.

Spec, not a wish

The prompt that ships.

You are building a Next.js flood-history app for a DRR portfolio. User: A resident of Kampung Melayu, Jatinegara. Purpose: See past flood events & typical impact for their kelurahan. Pages: One dashboard — event selector + risk verdict. Data model: events(id, year, tma_cm, rainfall, areas_hit, note). API: read events; classify risk from tma + rainfall. Stack: Next.js, TypeScript, Tailwind, Turso. Language: English. Seed: 5 labeled sample events. States: event picked → verdict; none → prompt to choose. Non-goals: no live TMA, no official warning, no auth. // Build Pass 01 only, then stop and report.

One pass at a time · verify · then continue.

Agent Skills

What is a Skill?

Definition

A skill is a packaged workflow + knowledge an agent loads on demand.

  • Not a plugin — nothing injected every run
  • Loaded only when the task matches

Recipe card

You don't read every card in the box — you pull the one whose title matches the dish. The agent reads SKILL.md and follows the workflow.

Skills map to the DRR pipeline

research

quick-research, websearch — build the evidence trail.

build

frontend-design, code skills — the interactive UI.

visual

generate-image — maps & assets.

evidence

datasheets-style data skills — structure the source trail.

MCP

What is MCP?

Model Context Protocol — an open standard for agents to connect to external tools & data.

MCP servers = live reach

  • Expose tools & data to the agent
  • Called like built-in tools, while it codes

In this project

  • Turso — read the events schema & seed
  • GitHub — repo, push passes
  • Cloudflare/Vercel — deploy
Skill

static procedure · by topic · "how to think"

MCP

live connection · by tool call · "what to reach"

Together: a skill defines the workflow — MCP gives it live data.
